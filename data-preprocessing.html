Section 01 • Clinical Data Quality

1. What is Data Preprocessing in Healthcare?

In textbook computer science courses, datasets arrive clean, balanced, and perfectly formatted. In real healthcare informatics, over 80% of modeling time is spent on data preprocessing. Real hospital records are notoriously heterogeneous—fraught with missing arterial blood draws, unit discrepancies (mg/dL vs. mmol/L), telemetric sensor disconnections, and physician documentation shortcuts.

⚠️ Garbage In, Fatal Out

In healthcare, bad training data doesn't just lower an accuracy metric—it misallocates intensive care beds, delays sepsis antibiotics, and perpetuates diagnostic biases.

🔢 Algorithms Speak Numbers

Mathematical estimators cannot multiply qualitative text strings like "Blood Type B" or "ICD-10 I21.0". Preprocessing systematically vectorizes qualitative EHR clinical charts.

⚖️ Equitable Metric Scales

Features measured on vast scales (Patient Age: 20–90) will mathematically overpower life-critical decimal biomarkers (Troponin: 0.01–0.40 ng/mL) unless standardized.

The Clinical Data Pipeline: Raw EHR vs. Clean ML Features

How raw, messy hospital observations are systematically transformed into high-performance machine learning inputs:

Section 02 • Clinical Imputation

2. Handling Missing Clinical Data (Imputation)

In non-medical data science, missing values are treated as accidental defects to be discarded. In clinical healthcare, the act of ordering or omitting a lab test is an informative clinical decision. Healthy patients have few lab orders; severely ill ICU patients receive frequent blood gas analysis and lactate monitoring.

Mechanism 01

MCAR: Missing Completely at Random

Missingness has zero correlation with patient state. Example: A blood tube was accidentally dropped on the lab floor, or a Wi-Fi telemetry packet dropped.

Safe for standard mean/median imputation.
Mechanism 02

MAR: Missing at Random

Missingness is predictable from other observed patient variables. Example: Troponin wasn't ordered because the patient presented for an elective knee replacement and has normal ECG vitals.

Requires multivariate imputation (KNN/MICE).
Mechanism 03

MNAR: Informed Missingness

The value itself causes the missingness. Example: A combative, acutely hypoxic patient was too agitated for a successful arterial blood draw.

Requires a binary Missingness Indicator column!

Univariate: Median vs. Mean

Fast & Robust

In healthcare, always prefer Median over Mean. Clinical biomarkers (D-dimer, serum creatinine, troponin) exhibit severe positive skew with extreme outliers from dialysis or sepsis patients that distort the mathematical mean. 

from sklearn.impute import SimpleImputer
import numpy as np

# Median preserves realistic biomarker baselines against outliers
imputer = SimpleImputer(strategy='median', add_indicator=True)
X_clean = imputer.fit_transform(X_vitals)

Multivariate: KNNImputer & MICE

Physiology-Aware

Instead of filling the same constant for every patient, KNNImputer finds the 5 patients with the closest matching age, blood pressure, and renal profile, and averages their values. 

from sklearn.impute import KNNImputer
from sklearn.preprocessing import StandardScaler

# Must scale before KNN distance calculation!
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)

imputer = KNNImputer(n_neighbors=5, weights='distance')
X_imputed = imputer.fit_transform(X_scaled)

Section 03 • Qualitative Variables

3. Encoding Categorical Clinical Data

Electronic Medical Records abound with qualitative categories: biological sex, ABO blood type, cancer staging, triage acuity, and primary diagnosis descriptions. To process these, we must strictly differentiate between Ordinal and Nominal variables.

Ordinal Variables: OrdinalEncoder

Rank Preserving

Variables with a natural clinical progression: Cancer Stage (Stage I < Stage II < Stage III < Stage IV), Pain (Mild < Moderate < Severe), or NYHA Heart Failure classes. 

from sklearn.preprocessing import OrdinalEncoder

# Explicitly define clinical progression
categories = [['Stage I', 'Stage II', 'Stage III', 'Stage IV']]
encoder = OrdinalEncoder(categories=categories)
X_ordinal = encoder.fit_transform(cancer_stages)

Nominal Variables: OneHotEncoder

Binary Dummy Columns

Variables with zero intrinsic ranking: Blood Type (A, B, AB, O), Hospital Ward (ICU, ER, Stepdown). Creates individual binary columns to avoid false arithmetic hierarchy. 

from sklearn.preprocessing import OneHotEncoder

# drop='first' prevents collinearity in linear models
encoder = OneHotEncoder(sparse_output=False, drop='first')
X_nominal = encoder.fit_transform(blood_types)
⚠️

The Fatal Healthcare Pitfall: LabelEncoder on Clinical Features

Never use LabelEncoder on feature inputs! If you encode Blood Types [A, B, AB, O] as [0, 1, 2, 3], you falsely instruct your machine learning algorithm that Type O is mathematically "three times larger" than Type B! LabelEncoder is strictly intended for the 1-D target array y.

Section 04 • Normalization & Standardization

4. Feature Scaling (StandardScaler vs. MinMaxScaler vs. RobustScaler)

In hospital databases, patient variables exist on radically different physical scales: Patient Age ranges from 20 to 90 years, Systolic Blood Pressure ranges from 80 to 200 mmHg, while Cardiac Troponin I ranges from 0.01 to 0.40 ng/mL. Without scaling, mathematical distance formulas assume that a 1-year age gap is 100 times more significant than a lethal troponin spike!

Before Scaling (Skewed Variance)

Raw Units

Age (range 20–90) completely warps Euclidean distance over biomarker (0.5–2.0 ng/mL).

After StandardScaler (Z-Score)

μ = 0, σ = 1

Both axes scaled symmetrically, ensuring equitable gradient steps and distance metrics.

StandardScaler

Z-Score Normalization

$$z = \frac{x - \mu}{\sigma}$$

Centers data so Mean = 0 and Variance = 1. Best for bell-shaped, Gaussian vitals (Blood Pressure, Heart Rate).

MinMaxScaler

Bound to [0.0, 1.0]

$$x_{\text{scaled}} = \frac{x - x_{\min}}{x_{\max} - x_{\min}}$$

Compacts variables into fixed boundaries. Excellent for image pixel intensities (0 to 255), but vulnerable to hospital outliers.

RobustScaler

Median & IQR

$$x_{\text{scaled}} = \frac{x - \text{Median}}{Q_3 - Q_1}$$

Mandatory for noisy clinical monitors. Ignores telemetric spikes (e.g. Heart Rate = 250 bpm artifact).

Section 05 • Medical Representation

5. Clinical Feature Engineering

Algorithms have no innate medical degree. Feeding raw numbers into a model is rarely enough; health informaticians engineer composite physiological biomarkers and temporal clinical context that capture clinical disease progression.

🫀

Physiologic Shock Index (SI)

$$\text{SI} = \frac{\text{Heart Rate (bpm)}}{\text{Systolic BP (mmHg)}}$$

A patient with HR 110 and SBP 95 has an SI of 1.16 (> 0.9 = Occult Shock). While both vitals individually seem borderline, their ratio signals life-threatening cardiovascular decompensation.

📅

Temporal & Shift Factors

is_weekend = admission_day >= 5

Captures the well-documented clinical "Weekend Effect" and night-shift staffing variations in intensive care units, accounting for operational delays in radiology and cardiac catheterization.

🧬

Multi-Organ Interaction Terms

Interaction = SBP * Creatinine

Captures systemic synergies (e.g., severe hypertension combined with failing renal clearance accelerates vascular end-organ damage exponentially rather than additively).

Section 06 • Class Asymmetry

6. Handling Extreme Class Imbalance (SMOTE vs. Cost-Sensitive)

In clinical epidemiology, life-threatening events are inherently rare: Sepsis in the emergency department occurs in ~2% to 4% of patients; acute in-hospital cardiac arrest occurs in ~1% of admissions. This creates the dangerous Accuracy Paradox.

Before Resampling (95% Negative)

Naive algorithms predict "Healthy" 100% of the time, achieving 95% accuracy while missing every patient.

After SMOTE (Synthetic Balance)

Synthetic Minority Over-sampling Technique interpolates synthetic patient feature vectors.

Method 1: SMOTE (Oversampling)

The Golden Rule: Never resample the validation or test set! Only resample X_train. The test set must preserve true clinical epidemiological prevalence. 

from imblearn.over_sampling import SMOTE
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, stratify=y)

# Only resample TRAINING cohort
smote = SMOTE(random_state=42)
X_train_res, y_train_res = smote.fit_resample(X_train, y_train)

Method 2: Cost-Sensitive Weights

Penalizes false negatives 50x more heavily inside the algorithm's loss function without generating artificial synthetic data points. 

from sklearn.ensemble import RandomForestClassifier

# Balances weights inversely to clinical class frequencies
model = RandomForestClassifier(class_weight='balanced', random_state=42)
model.fit(X_train, y_train)
