1.1

Mapping Clinical Problems to Machine Learning Paradigms

Match each healthcare scenario with the most appropriate machine learning task type.

Scenario A

Predicting the exact ICU length-of-stay (in days) following open-heart surgery.

Scenario B

Detecting diabetic retinopathy (Present vs. Absent) from fundus photography.

Scenario C

Discovering unknown subtypes of septic shock among 10,000 unlabelled EHR patient records.

Scenario D

Recommending optimal dynamic insulin dosages over time using blood glucose sensor feedback.

Reveal Clinical Solution & Rationale ▼
  • Scenario A → Supervised Regression: The target is continuous (number of days). Linear regression or gradient boosted trees predict numeric durations.
  • Scenario B → Supervised Classification: The target is categorical/binary (0 = Absent, 1 = Present). Evaluated with AUC-ROC, Sensitivity, and Specificity.
  • Scenario C → Unsupervised Clustering: There are no ground truth labels. K-Means or Hierarchical Clustering segments patients into physiological clusters based on multivariate vitals.
  • Scenario D → Reinforcement Learning (RL): Involves sequential decision-making where an agent takes action (insulin dose), observes reward/penalty (blood glucose in target range), and optimizes policies.
1.2

Clinical Case Challenge: Algorithmic Interpretability vs. Complexity

A cardiology department wants to deploy an automated bedside model to predict in-hospital cardiac arrest within 4 hours. The clinical director requires that bedside nurses and residents be able to inspect exactly which 3 to 4 clinical features triggered an emergency high-risk alert.

Question: Which model family would be most suitable to meet this regulatory and bedside interpretability constraint? Why would an ensemble of 500 Deep Neural Networks be problematic in this specific operational setting?
Reveal Solution & Clinical Explanation ▼

Recommended Model: A shallow Decision Tree or Logistic Regression with L1 (Lasso) Regularization.

Clinical Reason: A decision tree provides clear, intuitive if-then branch logic (e.g., Systolic BP < 90 mmHg AND Lactate > 3.5 mmol/L). Logistic regression coefficients provide direct Odds Ratios per unit increase of vital sign.

Why Deep Neural Networks Fail Here: While potentially achieving a 1-2% higher AUROC, deep networks operate as non-linear black boxes. In acute emergencies, clinicians will reject or override alerts they cannot quickly audit and verify.

Clinical EHR Preprocessing Challenges

2.1

Informing Missingness: When Mean Imputation is Clinically Fatal

In an emergency department dataset, 78% of incoming patients have a `NaN` (missing) value for Serum Troponin levels.

Question: Why would replacing missing Troponin values with the mean of the available values (\(\text{Mean} = 1.45 \text{ ng/mL}\)) severely distort clinical risk prediction? What does the act of missingness convey in medical practice?
Reveal Clinical Preprocessing Solution ▼

Clinical Mechanism: In hospitals, Troponin is an acute cardiac marker ordered almost exclusively when myocardial infarction is suspected. It is Missing Not At Random (MNAR).

Patients who did not have Troponin drawn were presenting with non-cardiac conditions (e.g. sprained ankle, dermatological rash) and typically have baseline normal Troponin (< 0.04 ng/mL). Imputing them with the mean (1.45 ng/mL) erroneously tags healthy non-cardiac patients as having massive acute cardiac necrosis!

Proper Preprocessing Strategy: Add a binary missingness indicator column (`troponin_was_ordered: 0 or 1`) and impute missing values with normal baseline 0.0, or use domain-informed clinical thresholds.

3.1

Preventing Data Leakage with Scikit-learn Pipeline

A student writes the following code to evaluate a sepsis classifier:

flawed_evaluation.py (Contains Leakage)
Python 
# Flawed Implementation (Full-cohort transformation):
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)  # <--- CRITICAL DATA LEAKAGE!
scores = cross_val_score(LogisticRegression(), X_scaled, y, cv=5)

Challenge: Identify the critical data leakage bug above, and rewrite this using `sklearn.pipeline.Pipeline` so feature scaling occurs strictly inside each cross-validation fold.

Reveal Correct Pipeline Implementation ▼

The Flaw: By calling `scaler.fit_transform(X)` on the full dataset, test fold distribution information (mean and standard deviation) leaks into the training step, producing artificially optimistic cross-validation scores.

leak_free_pipeline.py (Correct) Python 
# Correct Leak-Free Solution with Encapsulated Pipeline:
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score

pipeline = Pipeline([
    ('scaler', StandardScaler()),
    ('classifier', LogisticRegression())
])

# Scaler will now only fit on 4 folds and transform the 5th fold automatically
scores = cross_val_score(pipeline, X, y, cv=5, scoring='roc_auc')
print(f"Mean CV AUROC: {scores.mean():.3f} ± {scores.std():.3f}")

Diagnostic Confusion Matrix & Clinical Trade-Offs

4.1

Full Diagnostic Metric Calculation Drill

An AI model was evaluated on 1,000 mammograms for breast malignancy detection. The resulting 2x2 confusion matrix is shown below:

Predicted Malignant
Predicted Benign
Actual Malignant
TP = 80
FN = 20
Actual Benign
FP = 50
TN = 850
Calculate the following 4 metrics:
  1. Sensitivity (Recall) = TP / (TP + FN)
  2. Specificity = TN / (TN + FP)
  3. Positive Predictive Value (Precision) = TP / (TP + FP)
  4. Raw Accuracy = (TP + TN) / Total
Reveal Calculated Answers & Clinical Impact ▼
  • Sensitivity (Recall): \(80 / (80 + 20) = 80 / 100 = \mathbf{80.0\%}\)
  • Specificity: \(850 / (850 + 50) = 850 / 900 = \mathbf{94.4\%}\)
  • Precision (PPV): \(80 / (80 + 50) = 80 / 130 = \mathbf{61.5\%}\)
  • Raw Accuracy: \((80 + 850) / 1000 = \mathbf{93.0\%}\)
Clinical Interpretation: Notice that while overall Accuracy is high (93%), the model misses 20 out of 100 actual cancer patients (20 False Negatives). In clinical screening, missing 20% of malignancies is hazardous, proving why high Accuracy alone is misleading in imbalanced healthcare tasks.

Healthcare Mathematics & Probability Drills

5.1

The Base-Rate Fallacy in Clinical Diagnostic Testing (Bayes' Theorem)

A rapid antigen biomarker test for a rare autoimmune encephalitis has the following verified properties:

Prevalence \(P(D)\) 0.01 (1%)
Sensitivity \(P(T^+ \mid D)\) 0.98 (98%)
Specificity \(P(T^- \mid D^c)\) 0.95 (95%)
Drill Question: A newly admitted patient tests positive (\(T^+\)). What is the actual posterior probability \(P(D \mid T^+)\) that the patient truly has the disease?
Reveal Step-by-Step Derivation & KaTeX Math ▼

Apply Bayes' Theorem with Total Probability in the denominator:

$$P(D \mid T^+) = \frac{P(T^+ \mid D) \cdot P(D)}{P(T^+ \mid D) \cdot P(D) + P(T^+ \mid D^c) \cdot P(D^c)}$$
  1. Numerator: \(0.98 \times 0.01 = 0.0098\)
  2. False Positive Rate: \(P(T^+ \mid D^c) = 1 - 0.95 = 0.05\)
  3. Denominator: \(0.0098 + (0.05 \times 0.99) = 0.0098 + 0.0495 = 0.0593\)
  4. Result: \(\frac{0.0098}{0.0593} \approx 0.1652 \implies \mathbf{16.5\%}\)
Clinical Takeaway: Even with a 98% sensitive test, because the condition is rare (1% prevalence), more than 83% of positive tests are false positives! This proves why broad, unselected screening with AI for rare diseases leads to severe overdiagnosis unless pre-test probability is high.
5.2

Vector Euclidean Distance in Patient Similarity

Consider two diabetic patients represented in 2D standardized space: \(\mathbf{x}_1 = [z_{\text{HbA1c}}, z_{\text{BMI}}] = [2.0, 1.5]\) and \(\mathbf{x}_2 = [0.5, -0.5]\).

Calculation: Calculate the Euclidean distance \(d(\mathbf{x}_1, \mathbf{x}_2)\). What would happen to this calculation if raw unstandardized values (HbA1c: 6-12% vs. Platelet Count: 150,000-400,000) were used instead?
Reveal Solution ▼

Euclidean Distance Formula:

$$d = \sqrt{(2.0 - 0.5)^2 + (1.5 - (-0.5))^2} = \sqrt{(1.5)^2 + (2.0)^2} = \sqrt{2.25 + 4.00} = \sqrt{6.25} = \mathbf{2.5}$$

Why Standardization Matters: If raw values were used, platelet differences of 50,000 units would squared to \(2.5 \times 10^9\), rendering the HbA1c variance completely invisible to distance-based algorithms like KNN or K-Means.
